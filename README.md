# photo-guide

从相册选一张人物参考图，或在支持图片分享的应用中选择“photo-guide”。应用在手机上分析人物；然后打开系统相机，在可拖动的悬浮窗里查看参考图、半透明参考骨架和调整提示。拍照和保存照片仍由系统相机完成。

## 使用

1. 从小红书等应用保存图片到相册后选择，或使用对方提供的系统分享菜单发送单张图片。选择肩部和髋部清楚可见的单人照片；图片最大 40 MB。参考图和关键点保存在应用私有存储中，卸载应用会删除。
2. 点击“开始拍摄指导”。首次需在系统设置允许显示在其他应用上层；返回后再次点击。Android 13 及以上还会请求通知权限，拒绝后仍可通过悬浮窗关闭。
3. 每次开启都需接受系统的屏幕录制授权，建议选择**整个屏幕**，以便捕获系统相机。应用随即尝试打开系统相机；若未打开，请手动打开。将人物放入画面，拖动悬浮窗顶部以移动，按提示调整。点击悬浮窗“关闭”、通知中的“结束”，或系统录屏停止控件，均可结束会话。重新开始需要再次授权录屏。

## 原理和限制

使用 ML Kit Pose Detection 的 bundled 模型，模型随 APK 分发，图片和屏幕画面在端侧处理，无需 Google Play 服务或网络。参考图中检测到的关键点叠加在主界面和悬浮窗缩略图上；实时分析通过 MediaProjection 捕获屏幕画面，遮去悬浮窗区域后检测单人姿势，按躯干归一化比较手的高度，结合画面位置和躯干大小提示移动或远近。提示里的左右指**画面方向**，方便处理前置相机镜像。

第三方应用不能直接读取系统相机预览；录屏并不保证能读取相机画面。相机或系统可能将预览标记为安全内容、显示黑屏或禁止悬浮窗，ColorOS 的权限和后台策略也可能影响运行。录屏捕获的是整个屏幕，可能包含相机按钮和其他界面，选择单个应用、旋转屏幕、分屏、遮挡、多人物、局部身体、镜像及参考图与相机取景比例不同都会降低准确度；悬浮窗遮挡区域不会参与识别。建议竖屏、单人、完整躯干入镜，把悬浮窗移开人物。画面坐标比较只是近似构图建议，并非真实距离或三维姿态；当前只提供手部高度、左右位置和远近提示，不能可靠判断转身或全部关节。没有识别到躯干时会提示重新入镜。连续多帧几乎全黑时，悬浮窗会提示实时纠正不可用，仍可查看参考图。若相机控件可见而只有预览区域为黑色，可能无法自动识别；黑暗场景也可能触发该提示，画面恢复后会继续分析。屏幕录制期间系统可能显示录屏状态；结束服务后释放采集资源。应用不上传、不保存屏幕画面。

Android 14+ 使用 `mediaProjection` 类型前台服务，系统每次会话都要求新的授权；通知权限被拒绝时，前台服务仍会运行，通知可能不在通知栏显示。Android 15/16 仍受系统录屏、前台服务和悬浮窗限制。请勿在不希望屏幕内容被采集时开启，结束后再切换到其他应用。

## 构建与发布

需要 JDK 17、Android SDK Platform 35、Build Tools 35.0.0 和构建时的依赖下载网络。设置 `JAVA_HOME`、`ANDROID_HOME` 或 `local.properties` 的 `sdk.dir`：

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

仅打包 arm64-v8a，debug 与 release 均启用代码和资源压缩。APK 使用 debug 签名，不适合正式上架。推送 main 后 GitHub Actions 根据已有 `v0.0.N` tag 递增版本、构建并发布 APK；同一提交重跑复用 tag。不要移动或删除发行 tag。

## OPPO / ColorOS 测试

在 Find X9 实机上检查相册选择、从其他应用分享、首次悬浮窗和通知权限、每次录屏授权（选择整个屏幕）、相机预览是否可被录屏捕获、悬浮窗拖动及关闭、人物入镜后的提示、系统录屏停止、返回应用及重新开启。测试前后置相机、镜像、不同光线和遮挡；检查 ColorOS 的悬浮窗、通知和后台限制。应用尚未经该机型实测，实际行为以设备系统与相机策略为准。
